# Архитектура Metasiberia Social

Статус документа: рабочий черновик. Документ описывает фактическую архитектуру текущего fork OSSN и дополняется постепенно.

## 1. Границы проекта

`social.metasiberia` — fork Open Source Social Network (OSSN), работающий на PHP и использующий MySQL. На текущем этапе сохраняется штатная архитектура OSSN; изменения Metasiberia вносятся точечно.

Исходные репозитории:

- `origin` — `https://github.com/shipilovden/social.metasiberia.git`;
- `upstream` — `https://github.com/opensource-socialnetwork/opensource-socialnetwork.git`.

Коммиты и push выполняются только по отдельному разрешению.

Операционный runbook с локальным запуском, Ubuntu-схемой, сервисами, путями, БД и резервными копиями: [SREDA_LOCAL_AND_UBUNTU_RUNBOOK.md](SREDA_LOCAL_AND_UBUNTU_RUNBOOK.md).

## 2. Локальная среда

- веб-сервер: Apache из Laragon;
- PHP: `C:\laragon\bin\php\php-8.3.33-Win32-vs16-x64`;
- MySQL: `C:\laragon\bin\mysql\mysql-8.4.3-winx64`;
- локальный URL: `http://localhost/`;
- локальная БД: `ossn_metasiberia_local`.

Пароли, cookie, токены и другие секреты в этот документ не записываются.

## 3. Жизненный цикл запроса

Упрощённая схема:

```text
Apache
  -> index.php
  -> system/start.php
  -> OSSN route/page handler
  -> component hook и plugin view
  -> theme layout
  -> HTML + CSS + JavaScript
```

Основные точки расширения:

- `libraries/ossn.lib.initialize.php` — базовые страницы, меню и системные callbacks;
- `libraries/ossn.lib.components.php` — загрузка активных компонентов;
- `libraries/ossn.lib.views.php` — views и extension views;
- `libraries/ossn.lib.javascripts.php` и `libraries/ossn.lib.css.php` — регистрация и кэширование ресурсов;
- `themes/goblue/` — текущая тема и её layout, CSS и JavaScript.

## 4. Карта каталогов

- `actions/` — HTTP-действия и формы, включая login и административные действия;
- `classes/` — основные модели и сервисные классы OSSN;
- `components/` — функциональные модули социальной сети;
- `configurations/` — конфигурация установки;
- `libraries/` — системные функции и callback/hook-механизм;
- `system/` — базовые handlers, pages, forms и plugin views;
- `themes/goblue/` — пользовательская и административная тема;
- `vendors/` — сторонние библиотеки;
- `cache/` — сгенерированные CSS/JS-кэши, не являющиеся первоисточником логики;
- `docs/` — проектная архитектурная документация Metasiberia Social.

## 5. Пользователь и права доступа

В текущем OSSN есть два типа пользователей:

- `normal` — обычный пользователь социальной сети;
- `admin` — администратор сайта.

Ключевые проверки:

- `ossn_isLoggedin()` — пользователь вошёл в сеть;
- `ossn_isAdminLoggedin()` — текущая сессия имеет права администратора;
- `OssnUser::isUserVALIDATED()` — аккаунт подтверждён.

Новый пользователь до подтверждения имеет непустое поле `activation`. Обычный login в этом случае не выполняется и OSSN пытается отправить письмо подтверждения. Для локального тестирования пользователь подтверждается администратором через `/administrator/unvalidated_users`.

## 6. Главная страница и лента

Маршрут `/home` обрабатывается `ossn_user_pagehandler()` в `libraries/ossn.lib.initialize.php`.

Последовательность построения ленты:

1. проверяется авторизация;
2. загружается `OssnWall` из `components/OssnWall`;
3. содержимое передаётся в layout `newsfeed`;
4. layout находится в `themes/goblue/plugins/default/theme/page/layout/newsfeed.php`;
5. лента выводится в `.newsfeed-middle`, правая область — в `.newsfeed-right`;
6. под layout подключается общий footer `sibcore-site-footer`.

Разметка layout получает содержимое правой области через hook `newsfeed`, `sidebar:right`.
Если hook вернул непустое содержимое, создаются две колонки:

- `.newsfeed-col-wall` — `col-lg-8`;
- `.newsfeed-col-sidebar` — `col-lg-4`.

В CSS темы на ширине от 992 px эти колонки дополнительно переопределены примерно как 62,5% и 37,5%. Если содержимое правой области пустое, колонка sidebar не создаётся, а лента получает класс `.newsfeed-col-wall-centered` и центрируется. Поэтому обычный пользователь не получает пустого места справа. При наличии активного объявления лента остаётся слева, а объявление выводится справа.

## 7. Компонент рекламы `OssnAds`

Основной файл компонента: `components/OssnAds/ossn_com.php`.

Компонент регистрирует рекламные hooks для:

- правой области ленты (`newsfeed`, `sidebar:right`);
- правой области профиля;
- виджетов групп;
- глобальной правой области темы.

На странице ленты используется `getByPlacement('newsfeed')`. Перед выводом реклама фильтруется по статусу `approved`, сроку действия и, при наличии, полу пользователя.

### Кто может создавать и управлять рекламой

В текущей реализации только администратор:

- действия `ossnads/add`, `ossnads/edit`, `ossnads/delete` регистрируются только внутри `if(ossn_isAdminLoggedin())`;
- административная панель компонента открывается через `/administrator/component/OssnAds`;
- при создании объявления владелец объекта задаётся как `owner_guid = 1`, то есть системный администратор.

Обычный пользователь не может создать или изменить рекламную кампанию через штатный интерфейс.

Для страницы ленты административный CTA отключён: доступ к настройкам вынесен в отдельную иконку рупора в верхней панели. Иконка видна только администратору и ведёт на `/administrator/component/OssnAds`.

### Что именно показано на скриншоте администратора

Текст «Управление рекламой / Развивайте свое сообщество...» — это не рекламная кампания. Это административный CTA-блок из:

`components/OssnAds/plugins/default/ads/admin_create_sidebar.php`.

В исходной реализации он выводился из `ads/page/view.php`, когда активных объявлений в выбранном placement нет и текущий пользователь — администратор. Для placement ленты этот CTA теперь отключён; управление доступно через иконку рупора. Поэтому при отсутствии активной рекламы правая колонка ленты не резервируется.

## 8. Почему лента не по центру

Причина не в самом CTA-блоке и не в правах пользователя. Причина в layout:

```text
container-xl
  row
    wall: 8/12 (CSS примерно 62,5%)
    sidebar: 4/12 (CSS примерно 37,5%, даже если пусто)
```

При наличии активной рекламы правую колонку занимает рекламный блок. При отсутствии рекламы правая колонка не выводится, а лента центрируется.

## 9. Реализованная схема рекламы и ленты

В текущем fork реализованы следующие изменения:

- в верхней панели администратора добавлена иконка `fa-bullhorn` со ссылкой на настройки `OssnAds`;
- CTA «Управление рекламой» отключён именно для placement ленты;
- правая колонка ленты выводится только при наличии непустого содержимого;
- при отсутствии рекламы лента центрируется через `.newsfeed-col-wall-centered`;
- при наличии активной кампании placement `newsfeed` правая рекламная область сохраняется.

Общий footer фиксируется на авторизованных desktop-страницах, а `.ossn-inner-page` получает нижний отступ, чтобы последнее содержимое не перекрывалось footer. Правило применяется не только к ленте, но и к страницам друзей, фотографий, уведомлений, сообщений и другим страницам с тем же общим footer.

Механизм создания, хранения, таргетинга и показа активных рекламных кампаний не изменялся.

Для финальной проверки в браузере нужны два сценария: администратор без активной кампании и обычный пользователь без активной кампании — в обоих случаях лента должна быть по центру; после создания активной кампании placement `newsfeed` нужно проверить появление правой области.

## 10. Правило дальнейших изменений

Перед каждой правкой фиксируются:

- маршрут и роль пользователя, на которых проявляется проблема;
- component, hook, view и CSS, формирующие результат;
- ожидаемое поведение для `admin` и `normal`;
- минимальный набор изменяемых файлов;
- проверка локального HTTP, авторизации и затронутого layout.

Сначала меняется первоисточник в `components/`, `libraries/`, `system/` или `themes/`. Содержимое `cache/` пересоздаётся штатным механизмом OSSN и вручную не используется как источник логики.
